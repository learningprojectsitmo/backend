# Вопросы оценивания типов проектов

Вопросы относятся к существующему типу проекта конкретного учебного пространства. Проект выбирает этот тип через `project_type_id`. Преподаватель/admin настраивает его список вопросов; каждый вопрос имеет пять объяснений для баллов 1–5.

Есть три готовых набора:

| Код | Набор | Критерии | Объяснения | Максимальная сырая сумма |
| --- | --- | --- | --- | --- |
| `product` | Продуктовый | P1–P5 | 25 | 25 |
| `technical_integration` | Технический/интеграционный | T1–T5 | 25 | 25 |
| `research` | Исследовательский | R1–R5 | 25 | 25 |

Исходные названия, предмет оценки и все 75 объяснений сохранены в `src/data/assessment/question_templates.json`. Это готовые заготовки для копирования, без версии и без нового поля классификации ProjectType.

## Прочитать готовые наборы

```http
GET /v1/assessment/question-templates
Authorization: Bearer <access_token>
```

Возвращается массив в порядке product, technical_integration, research. Поля набора: `code`, `name`, `questions`. У критерия заготовки: `code`, `text`, `description`, `levels`. Каждый уровень содержит `score` и `description`, уровни всегда упорядочены от 1 до 5. Доступ требует входа; API записи заготовок отсутствует.

## Применить заготовку к типу

```http
POST /v1/workspaces/7/project-types/42/questions/apply-template
Authorization: Bearer <access_token>
Content-Type: application/json

{"template_code":"product"}
```

Операция **заменяет весь текущий список типа** пятью независимыми копиями. У копий новые DB id; повторное применение также создаёт новые id. Заготовка и вопросы других типов не изменяются. Автоматической синхронизации с заготовкой нет.

Применение доступно teacher/admin с правами на соответствующее пространство. Тип 42 должен принадлежать пространству 7. Типы с тем же названием в других пространствах независимы. Системные шаблоны типов с `workspace_id=null` через этот маршрут не настраиваются — используется конкретная копия типа в пространстве.

## Прочитать и настроить список

```http
GET /v1/workspaces/7/project-types/42/questions
Authorization: Bearer <access_token>
```

Ответ содержит `project_type_id`, `questions`, `min_score: 1`, `max_score: 5`. У вопроса есть `id`, `text`, nullable `description` (предмет оценки), `position` и пять `levels`.

Для редактирования передаётся **весь список** через PUT. У сохранённого вопроса передайте его `id`; у нового вопроса опустите `id`. Отсутствующие в запросе вопросы удаляются, а порядок массива задаёт позиции 0…N−1. `position`, `project_type_id` и прочие серверные поля не принимаются в теле.

Пример сохранения списка из одного собственного вопроса:

```http
PUT /v1/workspaces/7/project-types/42/questions
Authorization: Bearer <access_token>
Content-Type: application/json

{"questions":[{"text":"Обоснованность решения","description":"Аргументы выбора подхода","levels":[{"score":1,"description":"Обоснование отсутствует"},{"score":2,"description":"Обоснование фрагментарное"},{"score":3,"description":"Основной выбор объяснён"},{"score":4,"description":"Почти все решения обоснованы"},{"score":5,"description":"Решения полностью обоснованы"}]}]}
```

Чтобы дополнить готовый набор, сначала получите его скопированные вопросы через GET, передайте их с прежними id (без `position`) и добавьте новый вопрос в тот же массив. Можно менять тексты и объяснения существующих вопросов; их id сохранятся.

Количество собственных вопросов настраивается. Пустой массив допустим при настройке типа; готовность к проведению оценивания должна проверяться при подключении экзамена/листа.

## Валидация и права

- Текст вопроса: 1–1000 символов после trim. Предмет оценки: null либо 1–2000 символов. Объяснение уровня: 1–4000 символов.
- Для каждого вопроса обязательны ровно пять разных целых `score` от 1 до 5. Неполные/повторные уровни, дробь, строка или boolean вместо score, пустые объяснения и повторные id отвергаются.
- Ошибка в любом вопросе отменяет сохранение всего списка. Нельзя подставить id вопроса другого типа, передать чужой workspace/type или получить право записи через роль manager.
- Global admin работает с пространствами. Global teacher должен иметь доступ автора/участника. Локальные teacher/admin действуют только в своём workspace. Автор/участник может читать; manager/member без дополнительной роли teacher/admin не может записывать. Участник с NULL локальной ролью сохраняет право чтения.

| Ситуация | HTTP |
| --- | --- |
| Нет входа / неверный токен | 401 |
| Запись запрещена в доступном пространстве | 403 |
| Пространство/тип/вопрос отсутствует или чужой, системный тип по workspace-пути | 404 |
| Некорректное тело, id пути или неизвестный код заготовки | 422 |
| Успешный GET, PUT или применение заготовки | 200 |

## Хранение и согласованность

Миграция `d100a10b20c3` добавляет `project_type_question` и `project_type_question_level`. Старые типы, проекты и этапы не меняются; у существующих типов первоначально пустой список. Диапазон score, уникальность уровней, непустые тексты и позиции защищены ограничениями БД; полную шкалу из пяти уровней проверяет сервис сохранения.

Один запрос сохраняется одной транзакцией под блокировкой типа. Две одновременные записи выполняются последовательно; последняя успешная запись определяет весь список. Фиксация транзакции должна завершиться до успешного HTTP-ответа. История редакций рубрики не ведётся.

Downgrade удаляет новые таблицы вместе с настроенными вопросами и объяснениями; старые сущности сохраняет. Для проверок используется только отдельная временная БД.

## Границы поставки и приёмка

#100 реализует определения вопросов, готовые наборы, копирование и API настройки. Сохранение оценок участников, Exam, UI, расчёт и CSV относятся к следующим задачам. Для N вопросов сырая максимальная сумма 5×N; это не меняет автоматически максимум экзамена 25 и не утверждает формулу масштабирования.

Правила изменения/удаления вопросов, на которые уже ссылаются реальные оценки, должны быть определены при реализации листов. Этот шаг не заявляет защиту несуществующих листов или версионирование под другим названием.

Техническая приёмка включает: точность 3/15/75 и сумму 25; собственные вопросы/объяснения; независимость копий; матрицу ролей/workspace; стабильные id/порядок; полный откат, в том числе при ошибке commit; две реальные конкурирующие транзакции; upgrade/check/downgrade/upgrade и wheel вне repo.

Команды:

```sh
pytest tests/unit/test_question_templates.py tests/unit/test_question_schema.py tests/unit/test_project_type_question_service.py tests/unit/test_project_type_question_api.py tests/unit/test_uow_cleanup.py --no-cov
QUESTION_TEST_DATABASE_URL=... pytest tests/integration/test_project_type_questions_db.py --no-cov
ruff check src/ tests/
ruff format --check src/ tests/
pytest
```

DB-тесты создают свою случайную БД по явному `QUESTION_TEST_DATABASE_URL` с правом CREATE DATABASE, выполняют миграции только в ней и удаляют только её. Без переменной тесты пропускаются. В CI migrations job используется PostgreSQL 18; локальная проверка также выполняется на отдельной PostgreSQL 14.17. Итоговые команды/результаты и статусы каждого AC приведены в MR.
