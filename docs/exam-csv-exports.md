# CSV экзамена: ведомость команд и участие

Задачи [#121](https://github.com/learningprojectsitmo/backend/issues/121) и
[#122](https://github.com/learningprojectsitmo/backend/issues/122), CSV-контракт
[S0 #93](https://github.com/learningprojectsitmo/backend/issues/93).

## Скачать

```http
GET /v1/workspaces/{workspace_id}/exams/{exam_id}/exports/csv
Authorization: Bearer <access_token>
```

Ответ 200 — `application/zip`, `Content-Disposition: attachment; filename="exam-{exam_id}-csv.zip"`,
`Cache-Control: no-store`, `X-Content-Type-Options: nosniff`. Архив содержит ровно два файла:

1. `assessment-register.csv` — профиль `assessment-register.v1`;
2. `assessment-participation.csv` — профиль `assessment-participation.v1`.

Один запрос всегда готовит пару. Отдельных запросов на каждый файл нет: это сохраняет единый снимок.
Маршрут, ZIP, заголовки и лимиты — детали этой интеграции; в проверенном frontend main
`e4507fec37b4084306085c6217d9f8494e397ce4` другого контракта скачивания нет.

Доступ: эффективный teacher/admin с явным участием **в workspace экзамена**. Локальная роль приоритетна,
NULL использует глобальную. Авторство workspace само по себе недостаточно. Global admin вне workspace
и глобальный teacher с локальной ролью member не получают ведомости.

| Код | Причина |
|---|---|
| 401 | Нет аутентификации |
| 403 | Экзамен виден, но нет эффективной роли teacher/admin его workspace |
| 404 | Чужой/скрытый/несуществующий workspace или экзамен |
| 409 `audience_snapshot_unavailable` | У открывавшегося окна нет исторической аудитории: вся пара отклоняется |
| 409 `questions_missing` / `invalid_sheet_data` | Недоступные вопросы / несогласованные данные отправленного листа |
| 413 `csv_export_limit_exceeded` | Превышен лимит строк источников, ячеек или байтов |
| 422 | ID вне диапазона 1…2147483647 |

Ошибки БД/записи файла также не возвращают успешный или частичный архив.

## Общие поля и формат

Заголовки — стабильные машинные ключи, перечисленные в `src/services/exam_csv_profiles.py`.
Первые общие колонки: `schema_version`, `export_id` (UUID запуска), `snapshot_at` (начало транзакции UTC),
`workspace_id`, `exam_id`, `exam_title`, `registration_id`, `project_id`, `project_name`, `project_type_id`.
`export_id` и `snapshot_at` одинаковы у всех строк обоих файлов одного запроса.
Пустой экзамен даёт два файла с заголовками без строк; колонки критериев 1–5 присутствуют.

Используется общий [CsvExporter](csv-exporter.md): UTF-8 с одним BOM на файл, `;`, CSV-кавычки,
CRLF, UTC ISO 8601 с `+00:00`, decimal с точкой. `None` — пустая ячейка, реальный ноль — `0`
(integer) или `0.00` (сохранённый decimal). Потенциальные текстовые формулы защищаются апострофом.
Контакты, комментарии к ответам и содержимое черновиков не выгружаются.
Правила импорта Excel/LibreOffice — в документации общего writer; новая ручная проверка этих
доменных файлов в Excel/LibreOffice не проводилась.

Названия экзамена, проектов, типов и ФИО (имя, фамилия, отчество; пустые части пропускаются)
берутся из текущего состояния **того же снимка БД**. Исторических названий/ФИО в этих таблицах нет.
Для исторического допуска используются сохранённые роль, ID собственных проектов, допуск и причина.

## Ведомость команд

Одна строка на регистрацию, порядок `registration_id`. Источник — **все** регистрации экзамена,
включая `active`, `cancelled`, `moved`. LEFT JOIN сохраняет регистрации без попытки/окна/итога.
Реестр [#115](exam-results.md) не используется как основа, поскольку он отдаёт только завершённые попытки.

- `registration_status`, nullable `attempt_id`, `started_at`, `finished_at`, `postponed_at`, `queue_hold`;
- `presence`: `present`, если попытка началась; `no_show` при явном соответствующем queue_hold;
  иначе `unknown`. Отсутствие попытки не означает неявку;
- `defense_status`: статус попытки; без неё — `queue_hold` (`postponed`/`no_show`) или `not_started`.
  `queue_hold` отражает текущее состояние, после возврата в очередь старый hold не восстанавливается;
- `eligible_count`, `submitted_count`, `not_submitted_count`, `excluded_count` — уникальные люди текущей
  исторической аудитории. Пока окно не открывалось, все четыре поля пустые. Известный ноль — число;
- `decision_state`: `accepted` / `published` для сохранённого решения; `preliminary` для завершённой
  попытки без решения с расчётом, `no_calculation` при отсутствии учитываемых голосов, иначе `undecided`;
- `calculated_score` и `final_score` отдельно. Без решения итог пуст. Ручной итог допустим при пустом расчёте;
- `max_score`, `teacher_weight`, `manager_weight`, `member_weight`, `settings_version`, `sheet_max`;
- `result_id`, `result_version`, `result_kind`, `decided_by_id`, `decided_by_name`, `decided_at`, `reason`,
  `published_at`, `published_by`;
- `result_teacher_sheets`, `result_manager_sheets`, `result_member_sheets`, `used_weight` — параметры
  **сохранённого расчёта** (либо предварительного расчёта без решения). Они могут отличаться от текущих
  счётчиков участия, если после принятия были новые отправки.

Для сохранённого решения все его параметры читаются из **одной последней редакции** `ExamResultEdition`.
Новые настройки или отправки не подменяют её расчёт, максимум, веса и версии. Предыдущие редакции
не изменяются. Для предварительного результата переиспользуется `calculate_exam_score` (#113/#114),
текущие настройки экзамена, максимум листа `шкала типа × N` и те же отправки, которые видны в файле участия.
Для незавершённых/не начатых защит параметры настроек текущие; расчёт отсутствует.

## Участие

Одна строка на `(attempt_id, assessor_id)`, порядок регистраций, затем `assessor_id`.
Регистрация без попытки есть только в ведомости. Историческая аудитория читается целиком, включая исключённых.

| `response_status` | Допуск и поля отправки |
|---|---|
| `submitted` | `admitted=true`, последняя допустимая отправленная редакция, её версия/время/сумма/баллы |
| `not_submitted` | `admitted=true`, отправки нет; поля отправки пустые даже при черновике |
| `excluded` | `admitted=false`, сохранённая причина; поля отправки пустые |
| `not_requested` | Окно не открывалось; `admitted` и причина пустые, `audience_source=preview` |

`audience_source=snapshot` означает историческую аудиторию. До открытия окна предварительный состав —
текущие участники workspace с эффективной ролью admin/teacher/manager/member по тому же правилу, что при `finish`:
admin → teacher, локальная роль приоритетна. Это перечень людей, а не исторический допуск/обещание будущего допуска.
Старое окно без снимка никогда не восстанавливается по текущим связям.

`own_project_ids` — JSON-массив уникальных ID в числовом порядке, в одной ячейке. Для snapshot он исторический;
для preview — текущие авторство и участие в проектах этого workspace. Несколько связей не создают второй голос.
Teacher остаётся допущенным в собственную команду. Причины исключения сохраняются без переименования:
`member_of_defending_team`, `manager_of_defending_team`.

`submission_version`, `submitted_at`, `total` берутся вместе из последней по версии отправки допущенного оценщика,
которая попадает в `[opened_at, closes_at)`. Позднейший черновик её не заменяет. Баллы читаются только из её
`ExamAssessmentSubmissionAnswer`; проверяются полный набор ID вопросов и равенство суммы `total`.

### Произвольное число вопросов

`K = max(5, наибольшее N среди типов регистраций)`. Для каждой позиции 1…K:

- `criterion_i_question_id` — ID вопроса;
- `criterion_i_text` — текст;
- `criterion_i_score` — балл отправленной редакции или пусто.

Порядок вопросов: `position`, затем `id`, отдельно для каждого типа проекта. ID и текст присутствуют у строк
без ответа, баллы пустые. У более короткого типа неприменимые позиции полностью пустые. Никакого обрезания до 5
и объединения разных редакций нет. С первого окна вопросы типа заблокированы существующим доменным правилом.

Для каждой попытки с исторической аудиторией:
`eligible_count = submitted_count + not_submitted_count`; `excluded_count` равен числу строк `excluded`.
Те же строки используются для счётчиков и CSV. Для preview эти показатели не определены.

## Снимок, ограничения и ресурсы

Аутентификация использует обычный `AuthService` и отдельный короткий UoW, который закрывается до возврата пользователя. Она не держит соединение при получении снимка и скачивании. Сервис открывает **отдельный** UoW для снимка.
Первой командой устанавливается `SET TRANSACTION ISOLATION LEVEL REPEATABLE READ, READ ONLY`.
Права, настройки и все источники читаются в этой транзакции. Параллельные отправки/новые решения/настройки
между SELECT не разделяют состояние двух ведомостей. Timestamp — метаданные, изоляцию даёт PostgreSQL MVCC.

Лимиты одного запроса (ошибка 413 целиком):

- 100 000 строк суммарно из доменных источников (регистрации, последние редакции, вопросы, аудитория, ответы, preview);
- 1 000 000 ячеек профиля участия (консервативная оценка ширины до построения строк);
- 50 MiB суммарного **несжатого UTF-8** двух CSV, включая BOM/заголовки/кавычки/переносы.

DB LIMIT с резервной строкой ограничивает материализацию источников. Лимит ячеек предотвращает большой
декартов результат предварительного состава и попыток. Байтовый лимит проверяется перед каждой записью.
У writer остаются собственные ограничения поля/строки; `CsvExportLimitError` также превращается в 413, остальные ошибки writer сохраняют ошибку подготовки. Списки собственных проектов preview кодируются один раз на человека; их суммарное расширение по попыткам ограничивается 50 MiB до построения результата. Выгрузка, не укладывающаяся в лимиты, требует отдельного
решения по пакетированию, а не незаметного обрезания.

БД освобождается до сериализации. Оба CSV готовятся общим writer и упаковываются в worker thread до ответа 200.
Выдаётся полностью готовый ограниченный буфер `Response`. Временные файлы и поток с открытой БД не создаются.
Все внутренние буферы закрываются контекстными менеджерами, в том числе при ошибке второго CSV. При отмене
SQL-запроса UoW откатывается и закрывается; при отключении скачивания файловых/DB-ресурсов уже нет.
Это синхронная ограниченная по объёму подготовка, не фоновый экспорт.

## Проверка

```sh
REGISTRATION_TEST_DATABASE_URL=postgresql+asyncpg://user@localhost:5432/postgres \
  python -m pytest tests/integration/test_exam_csv_db.py tests/integration/test_exam_csv_http.py --no-cov
python -m pytest tests/unit/test_exam_csv_profiles.py tests/unit/test_csv_export.py --no-cov
ruff check src/ tests/
ruff format --check src/ tests/
```

Нужна отдельная PostgreSQL с CREATE DATABASE: fixtures создают и удаляют отдельную БД на сценарий.
`test_live_tcp_http_pair_reconciles_every_attempt_and_all_registered_states` запускает настоящий Uvicorn на
свободном localhost-порту, скачивает ZIP через HTTPX, разбирает оба файла CSV-парсером и сверяет счётчики.
Остальные HTTP-тесты используют ASGITransport с реальными сервисами/PostgreSQL; аутентифицированный actor
инъецируется тестовой зависимостью. Отдельно проверяются 401 без токена и настоящая Bearer-аутентификация с пулом из одного соединения: закрытие БД до ответа и три параллельных скачивания.
Тесты проверяют конкурентные отправки/решения, сохранение старой редакции, все статусы, роли/изоляцию,
N=1/5/7 и смешанные типы, формулы/кавычки/переносы, отсутствие/0, лимиты, сбой записи и отмену/отключение.

Технические проверки не являются записью мини-экзамена E08-T03. Ревью второго backend-разработчика
снято прямым решением Фёдора; проведённым оно не считается. Слияние PR и статусы доски — решение Фёдора.
