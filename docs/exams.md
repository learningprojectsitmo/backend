# Exam: экзамены пространства

Экзамен относится к workspace и содержит название, дату/время, описание, ссылку подключения, выбранные существующие типы проектов и настройки. Можно создать несколько независимых экзаменов. Источник вопросов — ProjectType этого workspace, без rubric_version, assessment_kind или копирования текстов в Exam.

## Создать и опубликовать

Все операции требуют Bearer token. База маршрутов: `/v1/workspaces/{workspace_id}/exams`.

```http
POST /v1/workspaces/7/exams
Content-Type: application/json

{"title":"Защита проектов","starts_at":"2026-11-30T07:00:00Z","project_type_ids":[42]}
```

Ответ201: `id`, `workspace_id`, `status:"draft"`, `current_settings_version:1`, `configuration`, `created_by/created_at`, nullable `published_by/published_at`.

Defaults: teacher/manager/member60/30/10, max_score `"25.00"`, выступление7 / вопросы7 / переход1 / оценивание3 минуты. Дата требует timezone; ответ UTC. В draft можно готовить пустой список типов. Для публикации каждому выбранному типу нужен непустой список вопросов с полной шкалой типа (1–3 или 1–5). Число вопросов произвольное.

```http
POST /v1/workspaces/7/exams/12/publish
Content-Type: application/json

{"expected_version":1}
```

Ответ200. Повторная публикация актуальной редакции сохраняет исходные published_at/published_by. Статус клиентом не задаётся. `status` фиксирует публикацию (`draft` / `published`). Фактический старт, завершение и архивирование передаются отдельными датами `started_at`, `completed_at` и `archived_at`.

## Прочитать

- GET базы: список `items,limit,offset,has_more`, defaults limit50/offset0, limit1…100; порядок starts_at,id. Необязательный фильтр `status=draft|published|completed|archived`. Обычный список исключает архив, `status=published` включает завершённые, а `status=archived` доступен организаторам.
- GET `/{exam_id}`: текущая конфигурация.
- GET `/{exam_id}/settings`: история version ASC, та же пагинация, только организатор.
- GET `/{exam_id}/settings/{version}`: конкретная редакция, только организатор.

Global admin может управлять всеми workspace. Global teacher должен быть автором/участником; local teacher/admin — своего пространства. Manager/member/NULL-role участник читают опубликованные экзамены; draft скрыт по id и в списке. Авторство пространства без teacher/admin не даёт запись. Чужой workspace/Exam/type недоступен. Чужие листы и оценки эти операции не предоставляют.

## Начать, завершить или архивировать

- `POST /{exam_id}/start` без тела, только организатор. Фиксирует фактическое начало опубликованного экзамена. Таймер защиты запускается отдельным запросом. Ответ 200 с `started_at`. Повтор до завершения или архивирования сохраняет дату. Для совместимости первая защита по прежнему API также фиксирует фактическое начало, если экзамен ещё не начат.
- `POST /{exam_id}/complete` без тела, только организатор. До фактического начала возвращает `409 exam_not_started`. Начатый экзамен можно завершить, когда каждая активная регистрация имеет завершённую попытку или отмечена как неявка. Ожидающая, идущая и отложенная защита дают `409 exam_queue_unresolved`. Ответ 200 с `completed_at`; повтор сохраняет дату. Запись, добавление слотов и ведение очереди больше недоступны. Уже открытые окна оценивания и работа с итогами продолжаются.
- `DELETE /{exam_id}` без тела, только global admin или admin этого workspace. Черновик без слотов и регистраций удаляется, повтор возвращает 404. Опубликованный экзамен или черновик со слотами архивируется. Оба варианта возвращают 204, повторное архивирование сохраняет дату. Архив сохраняет настройки, слоты, регистрации, попытки, листы и результаты. Прямые ссылки продолжают работать по прежним правам. Новые записи, защиты, слоты и правки настроек отклоняются с `409 exam_archived`. Уже начатую защиту можно довести до конца.
- Организатор может отменить незапущенную запись или перенести её из завершённого экзамена или архива в открытый экзамен. Исходная запись и событие сохраняются.
- Даты также доступны в `exam` live-снимка. Фактический старт есть и в `GET /{exam_id}/queue`. Мутации сериализуются общей блокировкой строки Exam.
- Миграция `d117a11b20a4` переносит в `started_at` время первой исторической попытки. Для ранее завершённых экзаменов без защиты сохраняется отметка времени завершения. Откат при наличии явного начала, не восстанавливаемого из этих данных, отклоняется.

## Изменить конфигурацию

PUT `/{exam_id}/settings` принимает expected_version, непустую reason и **полную** configuration из GET, включая nullable поля. Например, увеличить окно до5:

```json
{"expected_version":1,"reason":"Больше времени на оценивание","configuration":{"title":"Защита проектов","description":null,"starts_at":"2026-11-30T07:00:00Z","connection_url":null,"project_type_ids":[42],"registration_opens_at":null,"registration_closes_at":null,"weights":{"teacher":60,"manager":30,"member":10},"max_score":"25.00","presentation_minutes":7,"questions_minutes":7,"transition_minutes":1,"assessment_window_minutes":5}}
```

Ответ200 с новой current_settings_version. Старые редакции сохраняются; актуальный no-op не создаёт новую. Stale expected_version →409, включая повтор прежнего PUT после успешного изменения. Веса — целые0…100, сумма100; max_score положительный Decimal ≤2 знаков, JSON number/string; в ответе строка. Boolean/NaN/Infinity не допускаются. Длительности: выступление/окно1…1440, вопросы/переход0…1440 минут. Ноль отключает соответствующую фазу.

До фактического старта опубликованного экзамена организатор может изменить `starts_at`, `registration_opens_at` и `registration_closes_at`. Новый `starts_at` должен быть в будущем (`409 exam_start_must_be_future`). Существующие слоты и записи сохраняют свои ID и время. Если первый слот оказался бы раньше нового начала, сервер возвращает `409 slot_schedule_conflict`. После фактического старта сроки зафиксированы, а типы проектов фиксируются при публикации (`409 published_schedule_locked`). Если `registration_closes_at` равен null, конец самостоятельной записи определяется `starts_at`. Неподходящий период регистрации возвращает 422. Изменение создаёт редакцию с причиной. Title1…200, description null либо1…5000, connection_url null либо http/https≤2048, reason1…1000; строки trim. Типы только своего workspace, без повторов; системный тип с NULL workspace не принимается. При наличии registration timestamps: opens<closes≤starts_at, каждое≤starts_at.

## Интеграция записи и окна

`ExamService.require_self_registration_open(workspace_id, exam_id, user, now=server_time)` проверяет доступ, published и период от max(published_at,opens) до min(starts_at,closes), правая граница исключена. Фактический старт сразу блокирует самостоятельную запись, отмену и перенос, даже если до планового начала ещё есть время. #102 вызывает его в одной транзакции с созданием/отменой/переносом самостоятельной регистрации и отдельно проверяет manager/проект/тип/слот/уникальность. Сам guard эти проверки не выполняет. Организатор по решению пользователя управляет записью вне периода до фактического начала защиты; его registration API реализован в #103; пути и trusted claim — в инструкции записи.

`prepare_assessment_window(workspace_id, exam_id, project_type_id, expected_version=..., opened_at=server_time)` — внутренний доверенный вызов, без HTTP и самостоятельного commit. Проверяет опубликованный Exam, текущую редакцию, выбранный тип/готовность вопросов; блокирует весь список этого типа навсегда и возвращает frozen exam_id/workspace_id/project_type_id/settings_version/opened_at/closes_at.

#107 (реализовано) проверяет права ведущего, состояние попытки и связь проекта с типом и создаёт окно **в том же UoW**, сохраняя возвращённые времена/редакцию при завершении защиты; #111 использует сохранённый `closes_at`, аудитория — #104/#106. См. [инструкцию попытки](exam-attempts.md). Ошибка вставки окна откатывает новый lock. Пример: v1, открытие10:00, окно3 →10:03. Изменение v2 до5 не меняет этот срок; новое открытие10:02 по v2 →10:07. Идущая фаза таймера сохраняет свои метки в попытке, а не пересчитывается из новых настроек.

После первого окна PUT вопросов, очистка, добавление, перестановка, изменение объяснений и apply-template для этого типа отвергаются409. Для другого списка нужен другой тип. Это общая постоянная блокировка типа, включая другие Exam; снятия блокировки API нет. Тип, упомянутый в любой редакции Exam или marker блокировки, удалять нельзя. Операции сериализуются parent row locks; успешный HTTP-ответ даётся после commit.

## Ошибки

401 — нет входа; 403 — запись/история запрещена в видимом Exam; 404 — отсутствующий/чужой/скрытый объект; 422 — неверное тело/path/query; 409 — конфликт состояния. Detail409 содержит code/message:

- settings_version_conflict;
- questions_not_ready;
- published_schedule_locked, exam_start_must_be_future;
- slot_schedule_conflict;
- exam_not_published / registration_closed (внутренний guard);
- questions_locked (изменение списка вопросов);
- project_type_in_use (старый CRUD типа).

Неожиданная ошибка БД возвращает500, без ложного успешного сохранения.

## Хранение, проверки и границы

Миграция d101a10b20c4 от d100a10b20c3 добавляет exam, exam_settings_revision, exam_settings_project_type, project_type_question_lock и UNIQUE(id,workspace_id) типа. FK изолируют workspace и current revision; вопросные данные #134 не меняются. Downgrade теряет новые Exam/историю/lock, сохраняя старые типы/проекты/вопросы; применять обратный цикл только в собственной disposable DB.

```sh
pytest tests/unit/test_exam_schema.py tests/unit/test_exam_api.py --no-cov
EXAM_TEST_DATABASE_URL=... pytest tests/integration/test_exams_db.py --no-cov
ruff check src/ tests/
ruff format --check src/ tests/
pytest --no-cov
```

EXAM_TEST_DATABASE_URL указывает на тестовый PostgreSQL с CREATE DATABASE: fixture создаёт случайную exam_test_<uuid> и удаляет только её. Без переменной DB-тесты skip. CI проверяет PostgreSQL18; локально возможен14.17.

`exam.queue_revision` — монотонная ревизия снимка очереди; растёт при изменении состава/порядка/состояния очереди и не меняется при смене только слота. Снимок `GET .../queue` дополнительно содержит `settings_version` — текущую редакцию настроек, из которой взяты длительности ожидающих, ещё не начинавших защиту, а также `eta_stale`, `contract_version` и блок `eta`; смена настроек увеличивает `settings_version`, но не `queue_revision`. Очередь, откладывание, неявка и возврат описаны в [инструкции очереди](exam-queue.md), ETA и его актуальность — в [инструкции ETA](exam-eta.md).

Регистрации manager и явные слоты описаны в [инструкции записи](exam-registrations.md): self create/cancel/move/read/history, одна active запись проекта вообще. Старт/фазы/пауза/конец и сохранение окна описаны в [инструкции попытки](exam-attempts.md). Очередь реализована в #108 (`exam-queue.md`); аудитория, листы, расчёт, итоги, CSV и UI ещё не реализованы. Live-снимок #109 (`docs/exam-live.md`) отдаёт очередь/ETA/фазы/метаданные окон, но не аудиторию, листы или допуск. Счётчики проектов и оценщиков не возвращаются. Расчёт итога — `exam_score.py` (#113, [инструкция](exam-score.md)); принятие и публикация версий итога по попытке — #114 ([инструкция](exam-results.md)): принятый итог хранится до нового решения, расчёт заново идёт только при явном `accept`. Создание редакции настроек само по себе не пересчитывает результат. Общая сквозная приёмка и человеческое ревью учитываются отдельно.
