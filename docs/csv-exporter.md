# Общий CSV-компонент

`src.util.csv_export` записывает CSV по явно заданной схеме. Модуль использует стандартную библиотеку Python ≥3.14; он не зависит от SQL, HTTP и моделей оценивания. Разные профили передают одному `CsvExporter` свои колонки и одноразовый источник строк.

Общий контракт ещё требует командного согласования в [S0 #93](https://github.com/learningprojectsitmo/backend/issues/93). Здесь описано использование общего writer. Доменные выгрузки [#121](https://github.com/learningprojectsitmo/backend/issues/121) и [#122](https://github.com/learningprojectsitmo/backend/issues/122), их права, запросы и снимки результатов ещё не реализованы. Искусственные примеры ниже не являются этими выгрузками.

## Использование

Поток открывает и закрывает вызывающая сторона. Для предлагаемого формата Excel/LibreOffice она задаёт `encoding="utf-8-sig"` и `newline=""`; это даёт один BOM в начале нового файла. `CsvOptions` по умолчанию задаёт разделитель `;`, кавычку `"` и окончания записей CRLF.

```python
from decimal import Decimal

from src.util.csv_export import CsvColumn, CsvExporter, CsvOptions

columns = (
    CsvColumn("title", "Название", "text"),
    CsvColumn("amount", "Количество", "integer"),
    CsvColumn("change", "Коррекция", "decimal", nullable=True),
)
rows = iter([
    {"title": "Демо Альфа", "amount": 0, "change": None},
    {"title": 'Демо; "Бета"', "amount": -2, "change": Decimal("-1.25")},
])

with open("/private/tmp/demo.csv", "w", encoding="utf-8-sig", newline="") as target:
    stats = CsvExporter().write(
        columns=columns,
        rows=rows,
        target=target,
        options=CsvOptions(),
    )
    target.flush()

assert stats.row_count == 2  # Заголовок не входит в число строк.
```

`CsvColumn(key, header, kind, nullable=False)` определяет ключ, заголовок, тип и допустимость `None`. Поддерживаются `text`, `integer`, `decimal`, `boolean`, `datetime`. Каждая строка содержит ровно ключи схемы; nullable-поле присутствует со значением `None`. Лишние/пропущенные ключи, вложенные коллекции и значения неверного типа отклоняются через `CsvExportError`. Для decimal нужен конечный `Decimal`, для datetime — дата с timezone. Boolean не принимается вместо integer.

`None` записывается пустым полем, числовой ноль — `0`, boolean — `true`/`false`, decimal — с точкой, datetime — ISO 8601 с часовым поясом. Пустой источник сохраняет заголовок и даёт `row_count=0`. Источник читается один раз; порядок строк задаёт вызывающая сторона, порядок колонок — схема.

Writer не закрывает target, не выполняет `flush` за владельца и не управляет жизненным циклом HTTP-ответа. После ошибки в потоке уже могут находиться заголовок и часть строк. Для скачивания сначала следует полностью подготовить отдельный временный файл, выполнить `flush`, закрыть его и только затем отдавать успешный HTTP-ответ. При исключении файл удаляют; при скачивании владелец ресурса очищает его также после передачи/отключения клиента.

```python
from pathlib import Path
from tempfile import NamedTemporaryFile

from src.util.csv_export import CsvExporter

temporary_path = None
try:
    with NamedTemporaryFile(
        mode="w", encoding="utf-8-sig", newline="", delete=False
    ) as target:
        temporary_path = Path(target.name)
        stats = CsvExporter().write(columns=columns, rows=rows, target=target)
        target.flush()
    # Теперь temporary_path можно передать адаптеру скачивания.
    # После завершения ответа адаптер обязан закрыть и удалить файл.
except BaseException:
    if temporary_path is not None:
        temporary_path.unlink(missing_ok=True)
    raise
```

Во втором фрагменте `columns` и **новый** `rows` предоставляет вызывающий сервис: уже использованный одноразовый итератор повторно не читается. Контекстный менеджер закрывает поток и при исключении. Сам writer не проверяет права, не сохраняет редакции результатов и не держит транзакцию БД: для будущих доменных выгрузок это работа сервиса подготовки до сериализации. Ограничения доменного снимка по строкам и байтам требуют отдельного согласования S0.

## Ограничения и текстовые формулы

По умолчанию `max_field_chars=1_000_000`, `max_row_chars=5_000_000`: они ограничивают работу с отдельным полем и строкой. Лимит строки включает CSV-кавычки, разделители и окончание записи; проверка выполняется до её выдачи. Слишком большие строки/заголовки и коэффициенты/экспоненты Decimal проверяются до крупного преобразования. Writer не накапливает весь CSV или весь источник в памяти. Это не общий лимит числа строк/объёма файла и не гарантия ограниченной памяти стороннего источника данных.

`spreadsheet_safe=True` включает обработку текстовых значений и заголовков: перед потенциальной формулой добавляется апостроф. Проверяется начало после ведущих пробелов/управляющих символов: `=`, `+`, `-`, `@`; ведущие TAB/CR/LF также получают обработку. Значение в исходных данных не меняется, меняется текст в CSV. Настоящие отрицательные integer/Decimal остаются числовыми значениями без текстового апострофа. Обычные CSV-кавычки нужны для разделителей/переносов и сами по себе не предотвращают интерпретацию формулы табличным клиентом.

При `spreadsheet_safe=False` текст записывается без этой обработки. Такой режим следует выбирать только для заранее согласованного машинного потребителя; проверка Excel/LibreOffice относится к режиму по умолчанию. Реальное поведение формул и видимость апострофа в выбранных версиях клиентов ещё требуют ручной проверки. Повторное сохранение CSV сторонним клиентом может изменить представление.

## Два искусственных примера

Из корня backend, без editable-install проекта:

```sh
python scripts/generate_csv_examples.py --output-dir /private/tmp/eduflow-csv-examples
```

`--output-dir` обязателен; скрипт не создаёт CSV в репозитории по умолчанию. Он создаёт выбранную папку при необходимости, записывает/заменяет `teams-demo.csv` и `participants-demo.csv` через отдельные временные файлы и печатает только эти имена. Генерируемые файлы не следует коммитить.

Это два независимых искусственных профиля одного writer: 3 демо-команды и 4 условных участника D-01–D-04. Реальные люди и данные приложения не используются. Есть кириллица, кавычки, `;`, многострочная ячейка, пустое значение, настоящий ноль, отрицательные integer/Decimal и текст, похожий на формулу. Время фиксировано и условно. Названия/колонки не имитируют итоговую доменную ведомость или учёт голосов.

## Ручная проверка Excel и LibreOffice

1. Сгенерировать файлы командой выше и записать версии Excel/LibreOffice, ОС и локаль. Проверить каждый файл в обоих согласованных клиентах.
2. В Excel использовать **Данные → Из текста/CSV**: UTF-8, разделитель `;`, ограничитель текста `"`. Если доступен выбор типа колонки, импортировать текстовые колонки как текст, числовые — согласно профилю. Отдельно записать результат обычного открытия файла с настройками клиента по умолчанию: он может отличаться от импорта.
3. В LibreOffice Calc открыть файл через диалог импорта: кодировка UTF-8, разделитель `;`, ограничитель текста `"`. Зафиксировать настройки распознавания специальных чисел/формул. Проверить также типичное открытие без ручного принудительного перевода всех ячеек в текст.
4. Проверить 3 и 4 строки данных соответственно, по 6 колонок; кириллица, кавычки и `;` остаются внутри своих ячеек. Многострочная заметка занимает одну ячейку. Пустое значение не превращается в ноль. Отрицательные числа и Decimal остаются числами при согласованном числовом импорте; даты читаются вместе с timezone либо остаются явным ISO-текстом.
5. Тексты `  =SUM(1;2)`, TAB + `=1+1` и `@SUM(1;2)` должны отображаться как текст и не вычисляться. При просмотре строки ввода убедиться, что клиент не активировал формулу. Текстовый апостроф может быть виден: зафиксировать фактическое отображение. Принудительный текстовый импорт сам по себе не доказывает обработку формул при обычном открытии.

Пока эти действия не выполнены и результаты не записаны, совместимость и безопасность текстовых формул в Excel/LibreOffice не считаются проверенными.
